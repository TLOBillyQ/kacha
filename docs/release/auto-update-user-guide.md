# 自动更新用户指南

本指南说明 #3 的自动更新流程与 #14 的首次迁移交付。Windows `v0.3.0`（2026-10-09）是首个带 updater 签名的正式版，真实下载与签名已验证；完整安装、重启、恢复与迁移验收仍在进行，详见 [验收记录](auto-update-windows-acceptance.md)。macOS 首个带 updater 签名的正式版仍待发布，本文不表示它已经上线。

## 下载与网络

应用安装包及更新只从 [团队 Gitea Releases](http://lzxsvn:3000/qinyuanj/kacha/releases) 获取。现有 Gitea 和团队网关使用 HTTP，只能在可信内网或可信 VPN 中使用；HTTP 不提供传输加密。Updater 会验证更新包签名，但签名不替代可信网络要求。

发布附件中的 `SHA256SUMS` 用于手动核对下载文件。Windows 可在 PowerShell 执行下列命令，将结果与对应版本的 `SHA256SUMS` 比较：

```powershell
Get-FileHash -Algorithm SHA256 -Path .\kacha-<版本>-win-x64-setup.exe
```

Updater 签名与操作系统代码签名是两回事。项目没有购买 Windows 代码签名证书；macOS 应用仅 ad-hoc 签名，未经 Apple 公证。首次系统放行仍需手动完成。

## Windows 首次安装与旧免安装版迁移

支持 Windows 10 21H2+ / Windows 11 x64，应用依赖 WebView2。缺失运行时时按应用提示安装 Microsoft Edge WebView2，再启动 Kacha。

1. 从 Gitea Releases 下载带 updater 签名正式版的 `kacha-<版本>-win-x64-setup.exe`（首个为 `v0.3.0`）。旧 `kacha-<版本>-win-x64.zip` 不能直接接入新自动更新流程，需要手动安装一次。
2. 在旧版中等任务队列清空，保存全部已打开画板并退出。保留旧版程序及现有数据，便于必要时手动恢复。
3. 用原来的 Windows 用户运行 NSIS 安装器，按当前用户安装到该用户可写的目录。通常不需要管理员权限；应用不会自动提权。
4. 首次安装或启动如出现 SmartScreen 拦截，确认来自团队 Gitea 且校验值一致后，手动点「更多信息 → 仍要运行」。若系统策略不提供放行入口，交由团队维护者处理。
5. 从安装后的入口启动 Kacha，核对高级设置、API 密钥可用性、已打开画板及生成结果。之后使用安装版入口，避免误开旧免安装版。

迁移沿用原应用标识、应用数据目录以及系统凭据的服务与账户标识，继续使用同一输出根目录。高级设置、已持久化的 API 密钥、画板、任务目录与生成结果不迁到安装目录，也不要求重新填写密钥或移动输出文件。旧版仅在当前会话保存的密钥不等于已写入系统凭据的密钥，退出后仍需按原有方式重新输入。

## macOS 首次替换

仅支持 Apple Silicon。以下是首次迁移说明；macOS 真机安装、迁移与自动更新**未验收**，本次不执行，也不列为完成条件。macOS 构建、发布分支与相关脚本测试继续保留。

1. 等首个带 updater 签名的正式版发布后，下载 `kacha-<版本>-macos-arm64.zip`，按该版发布说明核对 SHA256。
2. 等任务队列清空，保存全部已打开画板并退出旧版。在访达解压，将 `Kacha.app` 手动替换到「应用程序」目录，即 `/Applications/Kacha.app`。保留旧版副本以备手动恢复。
3. 首次启动按 Gatekeeper 提示完成手动放行：在「应用程序」中右键或 Control 点按应用，选择「打开」并确认；若仍被拦截，按系统提示到「系统设置 → 隐私与安全性」选择「仍要打开」。
4. 用同一 macOS 用户启动并核对原高级设置、系统凭据、画板、任务目录与生成结果。应用数据及输出根目录保持原位置。

后续自动更新使用带 updater 签名的 `.app.tar.gz` 更新包，用户无需手动解压该更新包。应用目录不可写时，按下文从 Gitea 手动下载 zip 并替换应用。

## 日常自动更新

应用启动 3 秒后检查一次，持续运行期间每 6 小时检查一次。只选择更高版本的正式版，忽略草稿、预发布及相同或更旧版本。也可在「高级设置」点「检查更新」；没有新版时顶栏不额外提示。

发现新版后自动后台下载，期间可以继续创作。顶栏与高级设置展示同一更新状态，包括新版版本号、更新说明、下载进度、就绪提示与实际可获取的错误。下载完成并通过签名验证后出现「重启并更新」，仍需你主动点击。下载完成不会自动安装；生成任务结束也不会触发更新重启。

检查或下载失败时，更新入口显示原因，不弹窗打断创作。网络恢复后可手动检查或重试；签名校验失败的包不会就绪或进入安装。首版不支持断点续传，退出应用后不会保留下载内容，下次需重新检查和下载。

## 点击「重启并更新」之后

更新会检查跨所有已打开画板的全局任务队列。只要存在排队、执行中或限流退避的生成任务，包括读取参考图阶段，就阻止更新并提示「任务结束后可更新」。应用不会为更新自动取消生成任务。等任务结束后仍需你再次点击。

队列为空时，应用在准备和安装期间暂停新生成任务、画板修改与界面状态变更，并再次确认队列为空。随后处理待保存内容、等待正在进行的写入，并严格保存全部已打开画板与界面状态，包括此前保存失败的内容。全部保存成功才进入安装与更新重启。

任一画板或界面状态保存失败，都不安装、不重启，显示原因并恢复正常操作。先处理保存错误，再主动重试。更新后的全部已打开画板、活动画板与界面状态恢复是验收要求，当前真机证据仍待补齐。

## 安装失败或目录不可写

保留更新入口显示的实际错误。安装流程只展示官方插件可获取的结果，不承诺能检测所有安装器退出或新版启动失败。应用不会自动提权。

通过更新入口的手动下载链接，或直接进入团队 Gitea 对应 Release：

- Windows 下载 NSIS 安装器，保存画板并退出后，用同一用户安装到可写目录。
- macOS 下载首次安装 zip，保存画板并退出后，手动替换 `/Applications/Kacha.app`；没有写入权限时请维护者协助处理。

重新打开后核对版本、原高级设置、系统凭据、画板与生成结果。必要时从「高级设置」导出诊断包交给维护者，不直接分享 API 密钥。

## 新版无法启动时手动恢复

首版没有自动回滚、自动降级或新版启动健康检查，也不自动备份旧程序。到团队 Gitea 找到此前可用版本，核对该版校验文件后，按该版本的发布说明手动恢复：旧 Windows 免安装版解压后运行，已使用 NSIS 的版本手动安装，macOS 使用旧 zip 替换应用。

恢复前保留现有数据和输出根目录的副本，不删除应用数据或系统凭据。若旧版不能读取当前画板或数据，停止覆盖并联系维护者；保留原目录并不保证任意旧版都兼容新数据。自动更新不会替你完成这次恢复。
