# 画板变更是封闭联合类型，经唯一入口应用

画板编辑的规则（运行期锁定、图片端口同步、自动宽高比与撤销步同快照、撤销步的描述与归并）原先没有负责方：`BoardCanvas` 里叠了三级接受 updater 函数的入口，二十多个调用点各自带锁定守卫、label、merge key 并自选走哪一级，系统变更与改标题另走旁路，`updateNode` 等处漏了守卫只靠控件置灰，ADR 0012 的规则无从测试。我们改为：前端核心提供一个纯函数 `编辑(画板, 画板变更, 环境) → { 画板, 撤销步 | null, 提示?, 建议选中? }`，画板变更是封闭的联合类型（用户变更、系统变更、视图变更三类，见 `CONTEXT.md`），`useBoardSessions` 只留一个 `apply(画板键, 画板变更)`，不再有任何接受 updater 函数的画板写入口。一次变更属于哪一类、撤销步的描述与归并键是什么，由变更种类决定，调用方不能声明；`useRunner` 写入的提交记录与运行结果因此也是数据而非闭包。除视图变更外，所有变更走同一条后置管线（图片端口同步 → 自动宽高比重算），系统变更不另开特例。

运行期锁定是一条后置不变量而不是逐变更的守卫：变更算完后，任一锁定生成任务节点的参数（位置、尺寸除外）或输入连线与变更前不同、且该节点仍在，则整体拒绝、返回原画板与提示；系统变更豁免（提交记录正写在锁定任务上），「删除」变更里显式列入「连同取消」的锁定任务豁免。控件置灰从环境里的同一个锁定谓词派生，核心是准绳。

核心保持同步、纯：弹确认框、取消任务、选文件、读图片宽高与 sha 等副作用与异步事实由界面先做完，再把事实放进变更；采集失败就不产生变更。环境只含只读的能力表、每块画板的锁定集、图片宽高查询与 `newId`，由 sessions 层组装；时钟不进核心，撤销步由 `useBoardSessions` 拿返回的描述交给 `history.recordChange` 落账，`history.ts` 不动。撤销 / 重做是历史旅行而非画板变更，仍走 `mergeSystemState`（ADR 0012），不进联合类型。节点字段编辑拆成有语义的变更（编辑提示词、设分辨率档、设宽高比〔自动或具体值〕、设任务开关），生成尺寸由核心算，「选自动」不再有先写 1:1 再由外层改对的跨层中间态。

## Considered Options

- **保留 updater 函数，外加统一收口 `提交(画板, fn, 元信息)`**：改动小，后置管线同样能统一；但 label、merge key、变更类别仍由调用点给，「菜单 / 悬浮动作条 / 拖线三个入口做同一动作得同一结果」无法在核心测，闭包带出结果的写法（依赖 updater 同步恰好执行一次）也留着。否决。
- **逐变更写锁定守卫**：等于把现状搬进核心，新增变更种类时仍可能漏。否决，改用后置不变量。
- **核心内管 `History` 并注入时钟**：让编辑模块的测试都要带假时钟，且侵入已经够深的 `history.ts`。否决。
- **分步迁移、过渡期在联合类型里留 `{遗留, fn}`**：否决，选择一次性切换——单分支单 PR，先加核心模块与全量测试，再切界面与 `useRunner`，最后删旧入口；`ui/` 无 jsdom 测试，接线靠 PR 附的手测清单兜底。

## Consequences

- 联合类型约二十种变更，模块的深度在统一的前置校验与后置不变量，各变更的实现仍复用 `graph` / `iterate` / `dragCreate` / `selection` / `size` / `autoRatio`；要警惕它退化成只做转发的大 switch。
- 任务状态目前以任务节点 id 为键、不分画板，同一画板包导入两次会串锁；环境按「每块画板一个锁定集」设计，键的修正留给任务运行器的重构，届时本模块不用改。
