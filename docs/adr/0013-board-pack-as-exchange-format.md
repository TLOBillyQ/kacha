# 画板包是跨机器交换物，不改变任务目录为真源

美术需要把一块画板带到另一台机器继续工作，而 ADR 0010 让画板文件只引用任务目录、不自包含。我们不推翻 0010，而是另设「画板包」：单个 zip 文件，内部结构照搬输出根目录（`manifest.json` + `画板/<标题>.ugcboard.json` + 被画板节点直接引用的 `<日期>/<task_id>/` 整目录），不在任务目录里的参考图（根目录内外都算）按 sha256 去重复制进 `导入参考图/`、画板路径改写为该相对路径；包内只允许这几类条目，其他路径一律判为损坏，导入不会把文件放到根目录的任意位置。导入总是合并进本机当前输出根目录：已存在的 task_id 视为同一任务直接跳过（任务目录不可变、task_id 全局唯一，故导入幂等；`task.json` 不一致时报冲突不覆盖），同名画板自动改名、永不覆盖；更新的包或画板版本拒绝导入且不写任何文件；失败时已移入的完整任务目录保留、不回滚。包格式规则（布局、合并单元及其比对依据、计数）全在前端核心，Rust 壳只按给定条目与合并单元搬字节并守路径安全，与原 v2 规格（已删除）第 2 节「核心逻辑在前端」一致。

## Considered Options

- 画板文件自包含（图片内嵌或搬进画板目录）：0010 已否决，理由不变。
- 单 JSON 内嵌 base64 图片：体积膨胀约 33%，且无法直接复用任务目录结构排查。
- 导出时沿 `task.json` 的 `references[].source.path` 递归带上游任务目录：参考图快照已使每个任务目录自足，递归只补溯源信息，却可能把包撑到数百 MB；接受追溯链在包边界处断开。
