# 快照式撤销，系统写入的变更不进历史

画板的撤销 / 重做按整张画板快照记录，每个撤销步对应用户的一个意图（一次拖动、一次删除、一次迭代动作、一段连续输入），历史按画板独立、只在内存中、上限 100 步。生成任务完成时由队列写入的结果节点与系统连线、提交时写入的 `last_submitted` 不构成撤销步，也不清空历史；撤销或重做回到某个快照时，把当前画板里晚于该快照产出的结果节点及其系统连线合并回去（父任务已不在快照中的随之消失，任务目录里的图片不受影响）；排队 / 执行中的锁定任务及其输入连线同样按当前状态保留，不因撤销而改变已提交的输入；画板标题与视口不进撤销，撤销后按当前状态保留。选择快照而非命令式的理由是所有画板变更只有一个入口（原为 `updateBoard`，现为 ADR 0014 的 `apply`），快照不要求为每种操作写逆操作；系统变更排除在外，是因为让 Ctrl+Z 删掉刚生成的图会被美术误读为「图丢了」，而每出一张图就清空历史又等于没有撤销。代价是撤销后的画板不是任何历史时刻的精确状态，以及合并结果节点时需要按任务编号对齐。自动宽高比的重算（#120）也是系统变更：它随触发它的用户操作（接入 / 更换图1、改接线、增删区域指示、换模型或分辨率档）在同一次画板变更里完成，落进同一个快照；图片宽高晚于画板变更才读到时的补算按系统写入处理，不构成撤销步。用户在自动与手动之间切换则是一个撤销步。详见 `CONTEXT.md` 的「撤销步」。
