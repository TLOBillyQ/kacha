# 使用本地能力表约束网关模型

网关模型列表决定哪些模型当前可用，本地能力表决定每个模型允许的工作流、尺寸、出图数量和参数。网关可能不返回完整能力元数据，按模型名称猜测又会产生无效或收费请求，因此未知模型默认禁用；团队可以导入本地覆盖文件添加经过实测的模型，而无需重新发布整个客户端。

能力表记的是模型的事实（实测支持什么），不记客户端实现了什么：某项能力标为支持、但客户端尚未实现对应行为时（如区域指示的 `marked_image` / `bbox_tag`、未接入的请求形态），不改能力表，而由代码里的一处「客户端已实现」清单把它挡在外面。

Flash 专属准入按 ADR 0001 的 2026-10-10 例外：官方明确支持即可记为 `supported`，不把网关未测等同模型待测；只有实现并通过自动化验证的行为向用户开放。`region.ts` 的渲染清单与 `gateway.ts` 的 Flash 功能实现清单分别约束区域和专用透明/图层通路；#15 普通生成先行，#17–#20 已补齐区域、透明与图层通路并全部开放。证据按[Flash 研究](../research/seedream-flash.md)分别记录。其他模型维持实测准入，官方未明确能力仍 `untested`。
