# 任务目录为真源，画板为视图

任务记录、参考图快照、结果图、派生图与无结果任务的结局记录（`outcome.json`：失败类别或取消，用于重开时区分失败 / 已取消 / 已中断）只存在于任务目录（`输出根目录/<UTC 日期>/<task_id>/`），派发时写入、此后每个文件只写一次不可变；画板文件（`输出根目录/画板/<标题>.ugcboard.json`）只存节点、坐标、连线与脏判据快照，用相对路径 + `task_id` 引用任务目录，冗余的任务记录子集只供降级显示，冲突以 `task.json` 为准。删除画板、删除结果节点都不删任务目录。否决的候选是把图片与记录内嵌或搬进画板文件（画板自包含、可整体拷贝），理由是它会让同一张结果在多个画板间复制、脱离 v1 已有的任务目录追溯链，并把画板文件撑成 GB 级。代价是画板会遇到缺图：文件被移动或删除时节点保留占位、参与的任务不可运行，须由用户「重新定位」（只在输出根目录内按哈希 / `task_id` 找），切换输出根目录也不搬画板。详见原 v2 规格（已删除）第 9 节与 issue #59。

任务目录的格式知识（布局、文件名、任务记录形状与旧口径兼容）由前端核心的任务目录模块（`core/taskDir.ts`）独占，读与写同源；例外是诊断包的 Rust 侧，它只认 `task.json` / `outcome.json` 两个文件名与日期目录形状，因为诊断清单要由壳枚举文件，不值得为此新增目录列举端口。
